# 제안서 작업 안내 (공식 양식 대응)

2026년 9월 20일 개정: 이 폴더는 최초 참가 신청 때 사용한 기획 제안서 항목별 초안이다. 현재 기능심사 자료는 제공받은 공식 기능설명서 작성용 PPTX와 미리보기 PDF를 기준으로 별도 작성한다. 아래 최초 제안서 형식 안내를 현재 제출 조건으로 사용하지 않는다. 실제 구현·검증 범위는 `../PROJECT_PLAN.md`, `../VALIDATION.md`와 최신 공모전 안내를 따른다.

최초 참가 신청 당시 제안서는 **바탕 화면의 한글 파일**
`(양식1)『2026 관광데이터 활용 공모전』 제안서_팀명(대표자명).hwp`  
에 **작성항목·양식을 바꾸지 않은 채** 옮겨 적은 뒤, 공고에서 요구하는 **PDF(10MB 미만)** 로 내보내 제출한다.

- **파일명**: `팀명`·`대표자명`을 실제 정보로 바꿀 것.
- **이 폴더의 `.md`**: HWP 양식과 **항목 번호·제목이 같도록** 맞춘 **작성 초안**이다. 제출 시에는 HWP/PDF에는 **대괄호 안내·[초안용] 블록을 넣지 않는다.**

## 공식 제안서 목차 (① 웹·앱 개발 부문)

| MD 초안 파일 | 양식·공고 항목 |
|--------------|----------------|
| `01_기획배경_필요성.md` | **1)** 서비스 기획배경 및 필요성 |
| `02_서비스개요.md` | **2)** 서비스 개요 |
| `03_데이터활용방안.md` | **3)** 데이터 활용 방안 |
| `04_서비스발전방향.md` | **4)** 서비스 발전 방향 |

## 최초 제안서 작성 시 유의

- **분량**: **5페이지 이내** (이미지·표 포함)
- **글자**: **12포인트 이상**
- **형식**: **PDF**, **10MB 미만**
- **필수**: **지역 특화**이면 **2) 서비스 개요** 안 **4번** 반드시 작성

## 최초 제안서로 옮기는 순서

1. `01` → `04` 순으로 HWP 해당 칸에 붙여넣기  
2. `[초안용]`·대괄호 메모는 삭제  
3. 한글에서 글꼴·크기·페이지 수 확인 후 PDF 저장  

## 문서 동기화

코드·기획이 바뀌면 같은 작업에서 이 폴더 `.md`도 갱신한다. 기능심사 제출본에는 이 초안을 그대로 복사하지 않고 현재 구현된 기능과 실제 화면만 적는다.
