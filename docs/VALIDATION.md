# 구현 검증 기록

2026년 10월 17일 코드·문서 점검 기준. 자동 검증은 이날 다시 실행했다. 외부 API·운영 화면 확인은 아래에 명시한 과거 날짜의 결과이며 이번에 반복하지 않았다. 이전 개발 과정의 상세 로그는 Git 이력에 남아 있다.

## 최신 자동 검증

| 항목 | 10월 17일 결과 | 경계 |
|---|---|---|
| 백엔드 `pytest -q` | 104개 통과, 17개 제외 | 기본 실행. `STORYROUTE_TEST_DATABASE=1`이 필요한 DB 통합 테스트 등은 포함되지 않음 |
| 프런트 `npm test` | 12개 통과 | 브라우저 저장·길찾기·연결 재시도·시간 계산 유틸리티 |
| `npm run typecheck`·`npm run lint`·`npm run build` | 모두 통과 | Next.js 16.3.6 정적 페이지 7개 생성. 실제 운영 배포나 모바일 터치는 이 검사로 증명되지 않음 |
| 문서 링크·비공개 파일 확인 | 이 문서 정리 과정에서 별도 확인 | 상대 링크 대상과 면접 자료 Git 제외 여부를 최종 커밋 전에 점검 |

기본 테스트는 모의 관광·AI 응답을 쓰며 유료 API를 호출하지 않는다. 2026년 9월 30일에는 로컬 PostgreSQL 통합 옵션을 켠 별도 실행에서 **118개 통과**를 기록했다. 두 결과를 더하거나 운영 Neon DB에서 모두 실행한 것으로 설명하지 않는다. Alembic downgrade 자동 테스트는 SQL 생성 검증이며 실제 운영 DB를 되돌린 검증이 아니다.

## 실제 연결과 데이터 경계

- **9월 18일 AI:** OpenAI Responses API로 고정 예시 10개를 한 차례 평가해 모두 해당 시나리오의 조건 해석 기준을 통과했다. 일반 정확도나 반복 성공률은 아니다. 내부 ASGI 흐름에서 춘천 문장 해석→관광 후보 18개→두 장소 코스와 공식 소개의 인용문 대조를 확인했다. 실제 프런트 프록시를 통한 단일 AI 응답도 확인했다. 자세한 예시와 재실행 방법은 [AI 연결·평가](AI_SETUP_AND_CHECK.md)에 있다.
- **9월 18일 관광 데이터:** 국문 서비스의 강원도 코드 32와 18개 시군, 강원도 전체·춘천 실제 후보를 확인했다. 관광사진은 촬영지에 따라 묶었고 특정 관광지와 사진 ID를 동일시하지 않았다. 춘천향교의 Odii 원본 이야기 1개와 기준월 `202504` 연관 후보 5개, 무장애 정보가 있는 장소와 없는 장소를 확인했다. 누락 자료는 기본 상세를 막지 않는지 모의 응답으로도 검사했다.
- **9월 18일 이동:** 강원숲체험장→가보자순대국의 실제 카카오 자동차 응답에서 16,693m·1,505초와 도로 좌표를 확인했다. 조회 시점 예상값으로 현재 거리·시간을 보장하지 않는다. 잘못된 좌표, 부분 실패, 인증 오류, 순서 변경 후 재조회는 모의 응답과 화면에서 확인했다.
- **9월 18일 로컬 DB:** 프로젝트 전용 PostgreSQL 연결·한국어 데이터 읽기/쓰기와 장애 후 복구를 확인했다. 같은 날 다섯 테이블에 대해 제약·외래키·연쇄 삭제 등 16개 사례를 실행했고 확인용 데이터는 롤백했다. 이후 Docker Compose DB로도 연결을 확인했다. 이 기록은 운영 DB의 현재 상태가 아니다.
- **9월 30일 스키마:** 로컬·운영 Neon DB에 `20260930_01` NULL 허용 확인 컬럼을 적용하고 스키마 버전·컬럼 존재를 확인했다. 과거 사용자에게 확인값을 임의로 채우지 않았다.

## 화면과 운영 확인

- **9월 18일 관광사진:** 평창 검색에서 초기 세 페이지를 조회해 촬영지 묶음 8개·사진 72개를 확보했다. 브라우저에서는 로드 실패 이미지 5개를 제외한 67장이 목록에 남았다. 더 보기 후 촬영지 12곳·사진 115장을 확인했다. 320·375·768·1280px 화면 배치를 확인했지만 모든 이미지 다운로드 성공을 뜻하지 않는다.
- **9월 21일 첫 요청:** 공개 Render 문장 해석 API에서 유휴 후 첫 요청 55.66초, 직후 요청 1.89초를 관찰했다. 두 요청의 차이는 유휴 기동 지연의 단서이며 반복 측정이나 최근 요금제 성능을 대표하지 않는다.
- **10월 2~3일 카카오:** 기존 계정으로 로그인·새로고침·로그아웃과 별도 브라우저에서 저장 코스 6개 복원을 확인했다. 사용자 동의로 계정을 탈퇴한 뒤 같은 카카오로 다시 로그인해 계정 코스 목록이 비어 있음을 확인했다. 실제 다른 물리적 기기, 최초 사용 계정 가입, DB 삭제 행 수와 복구본 삭제까지 확인한 것은 아니다.
- **10월 3일 시간 계획:** 첫 장소 도착 시각·체류 시간을 바꿔 예상 시각이 다시 계산되는지 화면과 프런트 테스트에서 확인했다. 입력값은 코스 DB에 저장되지 않는다.
- **10월 4일 장소 사진:** 390×844 로컬 화면에서 카드의 추가 사진·전체 화면·방향키 조작과 원본 교체를 확인했다. 마우스 드래그로 스와이프를 모의했으며 실제 휴대전화 터치 확인은 별도로 필요하다. 공개 화면에서도 인제군 카드의 전체 화면과 사진 번호를 확인했다.
- **10월 5일 지도·화질:** 로컬·공개 화면에서 지도 깊이감과 모바일 가로 넘침을 확인했다. 지도 효과는 장식이며 실제 지형 높이가 아니다. 인제군 카드에서 가로 300px 이미지를 약 356 CSS px로 표시해 흐릿했던 사례를 찾고, 원본 940px로 교체되는 것을 로컬·공개 화면에서 확인했다. 제공 원본이 저해상도이면 더 선명하게 만들 수 없다.
- **10월 9일 문의처:** 공개 `/privacy`에서 전용 메일 주소와 `mailto:` 표시를 확인했다. 이후 사용자가 메일 테스트를 완료했다고 알려왔다. 송수신 세부 결과와 대응 절차는 이 점검에서 직접 확인하지 않았다.

## 아직 확인하거나 개선할 것

1. 처음 쓰는 카카오 계정의 가입과 닉네임 선택, 다른 물리적 기기에서 계정 코스 열기, 장시간 세션 유지와 운영 DB 복구 절차를 별도 검증한다.
2. 실제 휴대전화 터치 스와이프와 오디오 끝까지 재생, 다양한 문장·부정 표현에 대한 AI 품질을 확인한다.
3. 계정 저장 API의 TourAPI 장소 재검증, 목록 반복 쿼리, 저장 중복 방지, 인증·계정 요청 제한을 개선한다. 현재 구현 경계는 [DB 구조](DATABASE_SCHEMA.md)와 [프로젝트 계획](PROJECT_PLAN.md)에 있다.
4. 외부 서비스 지연·실패율, 첫 요청 시간과 이미지 다운로드 시간을 반복 측정한다. 단일 관찰값을 성능 보장으로 사용하지 않는다.
5. 방문 완료·메모는 사용자 직접 입력이며 브라우저에만 저장된다. GPS 인증이나 기기 간 동기화로 설명하지 않는다. 외부 정보 누락을 시설 없음으로 단정하지 않는다.

## 다시 실행할 때

프로젝트 루트에서 `python -m pytest -q`, 프런트 `web`에서 `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`를 실행한다. 실제 관광·AI 호출은 [README](../README.md)의 별도 명령을 사용하며 인증키·사용량을 확인한 환경에서만 실행한다. DB 통합 검증은 로컬 전용 DB를 준비하고 `STORYROUTE_TEST_DATABASE=1`을 명시한 별도 실행이다. 운영 DB에 테스트 데이터를 넣지 않는다.
