# StoryRoute 디자인 기준

2026년 10월 17일 문서 정리. 기존에 정한 색상과 디자인 방향을 유지하고 반복된 설명을 합쳤다. 이 문서는 디자인 기준이며 모든 항목의 구현 완료를 뜻하지 않는다.

## 목표와 우선순위

첫인상은 깔끔하고 정돈된 여행 서비스여야 한다. 넓은 여백과 읽기 쉬운 글자, 사진과 다음 행동을 중심으로 구성하고, 배경의 따뜻함과 작은 단풍 장식으로 가을 분위기를 더한다. 기본 UI가 80~90%, 계절 장식이 10~20% 정도의 비중을 갖는 것을 목표로 한다.

규칙이 충돌하면 사용성·접근성, 기존 디자인 시스템, 컴포넌트 일관성, 본문 가독성, 계절 표현, 장식 순서로 판단한다. 장식 때문에 검색·선택·저장·길찾기가 늦게 눈에 들어오면 줄인다.

## 색상과 배경

| 토큰 | 권장 색 | 용도 |
|---|---|---|
| `--autumn-background` | `#FFFCF8` | 따뜻한 페이지 배경 |
| `--autumn-cream` | `#FAF5EE` | 매우 연한 영역 구분 |
| `--autumn-beige` | `#F1E8DC` | 작은 배경 디테일 |
| `--autumn-orange` | `#D9A875` | 낮은 채도의 계절 장식 |
| `--autumn-brick` | `#B98267` | 단풍·작은 강조 |
| `--autumn-brown` | `#8F7461` | 작은 장식·보조 표현 |
| `--autumn-olive` | `#929176` | 제한적인 보조 장식 |

계절 토큰은 기존 `primary`, `danger`, `success`, `warning`, `surface`, `text`를 대체하지 않는다. 주요 버튼의 기능 색상은 유지하며 모든 버튼·입력창·카드를 주황색이나 갈색으로 바꾸지 않는다. 한 화면의 눈에 띄는 계절 강조색은 하나, 필요한 경우 최대 둘로 제한한다.

페이지는 따뜻한 흰색이나 미색을 기본으로 하고 카드·입력 영역은 중립색을 유지한다. 모든 영역을 서로 다른 가을색으로 칠하지 않는다. 소개 영역의 아주 약한 흰색→미색 변화는 허용하지만 강한 주황·빨강·갈색 그라데이션은 사용하지 않는다.

## 단풍 장식

단순한 선, 평면 실루엣 또는 일부만 보이는 SVG를 사용한다. 권장 불투명도는 0.025~0.06, 최대 0.08이다. 첫눈에 장식부터 보이면 강도를 낮춘다.

- 사용할 곳: 소개 영역, 페이지·섹션 배경, 빈 상태, 푸터와 넓은 여백.
- 피할 곳: 입력창, 표, 모달, 메뉴, 검색 결과, 정보가 많은 카드, 버튼 내부와 텍스트 바로 뒤.
- 데스크톱 2~3개 정도를 사용한다면 모바일은 1~2개로 줄인다. 콘텐츠와 겹치면 숨긴다.
- 실제 낙엽 사진·사실적인 질감·수채화·광택·빛 번짐·무거운 그림자·3D 잎 장식은 사용하지 않는다.
- 낙엽이 계속 떨어지거나 떠다니는 애니메이션, 시차 효과, 회전·입자 효과는 사용하지 않는다.

장식은 기존 콘텐츠의 폭·정렬·여백을 바꾸는 이유가 되지 않는다. `web/public/maple-leaf.svg`를 수정할 때도 이 기준을 따른다.

## 컴포넌트와 글자

버튼·입력·탭·카드·모달·토스트·내비게이션은 기존 컴포넌트를 재사용한다. 계절감을 이유로 글자 위계, 간격, 모서리, 테두리, 포커스, 비활성·오류 상태를 바꾸지 않는다.

카드는 중립 배경과 얇은 테두리를 기본으로 하고 그림자는 최소화한다. 카드 전체를 베이지·주황·갈색으로 채우거나 단풍 패턴을 반복하지 않는다. 장식용 세리프·손글씨 글꼴을 추가하지 않는다. 버튼은 현재 단계에서 가장 중요한 행동이 먼저 보이게 하고, 방문 정보·이야기·편의정보 같은 보조 기능이 모두 같은 강도로 경쟁하지 않게 한다.

## 모바일과 동작

장소 사진과 이름, 선택 상태, 다음 행동이 좁은 화면에서도 분명해야 한다. 긴 로그아웃 글자나 여러 보조 버튼 때문에 헤더가 깨지지 않게 한다. 아이콘만 보이는 버튼은 접근 가능한 이름을 유지한다.

지역을 눌렀다는 이유만으로 화면을 강제로 아래로 이동시키지 않는다. 사진 넘기기는 터치·마우스·키보드로 사용할 수 있어야 한다. 저장 후 성공·실패를 알리고 메모 유무는 접힌 상태에서도 구분한다. 짧은 상태 전환 외에 지속적인 움직임을 두지 않으며 `prefers-reduced-motion`을 고려한다.

다크 모드를 추가한다면 밝은 크림 배경을 그대로 옮기지 않고 어두운 중립색과 낮은 채도의 장식을 사용한다. 다크 모드 제공 자체는 현재 기능으로 가정하지 않는다.

## 지도 표현

첫 화면의 강원도 시·군 지도에는 경계 아래의 얇은 면과 약한 그림자로 깊이감을 준다. 데스크톱에서만 약하게 기울이고 모바일에서는 기울임 없이 지역명과 선택 영역을 읽기 쉽게 유지한다. 실제 지형 고도를 표현한 3D 지도는 아니다.

코스 지도에서는 방문 순서 점선과 실제 자동차 도로 경로를 구분한다. 지도·시간 정보가 지나치게 아래에 묻히지 않게 하며, 경로를 조회하지 않은 상태를 실제 이동 결과처럼 표시하지 않는다.

## 화면 검토 기준

검색 입력, 결과, 상세, 코스·여행 화면을 모바일과 데스크톱에서 각각 확인한다. 첫 화면뿐 아니라 긴 장소명·정보 누락·느린 요청·오류·사진 없음·메모 작성 상태에서도 가로 넘침과 버튼 혼잡이 없는지 확인한다. 실제 화면 검토 결과는 [검증 기록](VALIDATION.md)에 남긴다.
