# 최소 사용자 시나리오

2026년 9월 17일 · 1인 개발 · 강원도 당일 여행 · 실제 Tourism 저장소 기준

현재 강원특별자치도 전체 검색과 18개 시군 선택을 지원한다. 실제 연결 확인과 미확인 항목은 [검증 기록](VALIDATION.md)을 따른다.

## 완주할 흐름

사용자는 ‘바다도 보고 식사도 하는 하루’를 만들고 싶다. 회원가입 없이 접속하고, 문장을 입력하거나 직접 조건을 고른다. 해석된 관심 유형·키워드를 확인하고 수정한다.

실제 관광 API에서 강원도의 장소 후보를 조회한다. 강원도 전체 또는 선택한 시군을 기준으로 검색하며, 이름·분류·주소·사진 누락 여부와 근거를 확인하고 상세를 열 수 있다. 최대 세 장소를 고르고, 특정 장소가 마음에 들지 않으면 현재 후보 안의 다른 장소로 바꾼다. 한두 장소로도 완성할 수 있다.

코스 만들기를 누르면 서버가 장소 ID·유형·지역·존재 여부를 다시 검사한다. 실제 소개와 대조한 AI 단서 또는 확인된 사실이 보인다. 사용자는 방문 순서를 바꾸고 지도 마커와 외부 길찾기를 확인한 뒤 이 브라우저에 저장한다.

저장한 코스를 다시 열면 실제 장소 정보를 재조회한다. 조회 실패나 사라진 장소는 안내한다.

## 사진과 이야기로 발견하기

입력 화면에서 관광사진을 지역·키워드로 둘러보고 ‘이 지역 장소 찾기’로 실제 관광 후보를 검색한다. 사진 ID나 촬영지 문자열만으로 정확한 지도 위치를 표시하지 않는다.

장소 상세의 ‘이야기 듣기’에서는 관광지명과 제공 좌표를 대조한 오디 원본 대본·음성을 확인한다. ‘함께 볼 곳’에서는 기준월 연관 자료를 살펴본다. 국문 관광정보에서도 이름·지역을 확인한 장소만 후보로 연결하고 사용자가 직접 선택한다. 조건이 다른 장소를 살펴보면 새 검색 조건을 준비하고 이전 선택 초기화를 안내한다.

## 예외 상황

- AI가 없거나 실패하면 직접 조건을 확인하고 검색한다.
- 관광 연결이 없으면 실제 후보를 제공한 것처럼 표시하지 않는다.
- 빈 결과·사진 없음·좌표 없음·대체 후보 없음은 각 상황에 맞게 안내한다.
- 새 검색이 실패하면 이전 결과와 적용 조건을 유지한다.
- 저장에 실패하면 성공 메시지를 표시하지 않는다.
- 사진·오디·연관 조회 실패나 빈 결과는 해당 영역에서 안내하며 기본 여행 검색을 유지한다.

## 반응형 기준

모바일은 카드 한 열과 코스 목록 다음 지도, 태블릿은 카드 두 열, PC는 목록과 선택·지도 영역을 나란히 배치한다. 고정된 휴대폰 틀 없이 같은 기능을 사용할 수 있어야 한다.

## 완료 기준

입력 → 수정 → 실제 검색 → 선택·교체 → 코스 검증 → 순서·지도 → 저장·복원이 이어져야 한다. 서버 저장·공유 링크·전국 지도·사진 인식은 이후 확장이다.

최신 범위는 [개정 기획서](PROJECT_PLAN.md), 실제 파일·API는 [프런트·API 설계서](FRONTEND_API_SPEC.md)를 따른다. 과거의 2인 개발·5월 접수 기준을 현재 일정으로 사용하지 않는다.
