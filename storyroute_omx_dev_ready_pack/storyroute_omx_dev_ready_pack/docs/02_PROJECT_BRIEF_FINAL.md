# 02. 프로젝트 기획서 Final — StoryRoute AI

## 1. 서비스 정의

StoryRoute AI는 한국관광공사 공공데이터를 중심으로, 사용자의 모호한 여행 요구를 **이해 가능한 추천 + 생성 가능한 일정**으로 바꾸는 여행 탐색 서비스다.

## 2. 핵심 문제

여행자는 장소를 찾는 것보다 **장소를 이어 붙이는 것**에서 더 많은 시간을 쓴다.

- 부모님과 가는지
- 아이와 가는지
- 얼마나 걷는지
- 어떤 분위기를 원하는지
- 1박 2일인지 당일치기인지

이런 조건이 들어오면 단순 키워드 검색은 한계가 있다.

## 3. 해결 전략

StoryRoute AI는 세 레이어를 결합한다.

### 1) 검색 레이어
- keyword + semantic search
- 지역/속성/제약 필터 동시 처리

### 2) 관계 레이어
- 연관 관광지 / 중심 관광지 데이터 기반 graph expansion
- 장소 단건 추천이 아니라 코스 후보 생성

### 3) 플래너 레이어
- 사용자 제약을 구조화
- 일정 길이, 이동량, 카테고리 다양성 반영
- explainable itinerary 생성

## 4. 왜 이 프로젝트가 공모전에 맞는가

1. 한국관광공사 데이터를 단순 조회가 아니라 **canonical source**로 사용한다.
2. 연관 관광지와 중심 관광지로 **graph-based itinerary**를 만든다.
3. 스토리텔링/오디오/설명 데이터를 활용해 **설명 가능한 추천**을 제공한다.
4. 저장/공유/수정 로그를 적재해 공공데이터 위에 **서비스 자체 데이터 자산**을 쌓는다.

## 5. 핵심 차별점

### 차별점 A — 모호한 질의 처리
"부모님과 경북 1박 2일, 많이 걷지 않고 야경 좋은 곳"
같은 문장을 바로 itinerary 후보로 전환한다.

### 차별점 B — explainable recommendation
추천 이유를 단순 태그가 아니라 문장으로 보여준다.

### 차별점 C — 지역 특화 확장
경북/강원/제주처럼 지역 랜딩을 별도로 구성할 수 있다.

### 차별점 D — 운영 데이터 축적
어떤 intent가 저장/공유로 이어지는지 누적해 추천 성능 개선에 활용한다.

## 6. 대표 데모 시나리오

### 데모 1 — 홈
사용자가 자연어 질의를 입력한다.

### 데모 2 — 검색 결과
semantic search + filter + map + reason card가 동작한다.

### 데모 3 — 장소 상세
관광공사 데이터 기반 기본정보 + AI 요약 + 스토리 + 주변 추천이 나온다.

### 데모 4 — 플래너
일자별 itinerary가 생성되고 수정 가능하다.

### 데모 5 — 지역 특화
경북 특화 랜딩에서 대표 의도, 코스, 스토리를 보여준다.

### 데모 6 — 관리자
검색 의도, itinerary 생성률, 저장률, 공유률을 본다.

## 7. 데이터 전략 요약

- raw snapshot 보존
- `place` 중심 canonical model
- search chunk / embedding 분리
- 관계 데이터는 graph table로 분리
- 사용자 이벤트/추천 결과를 fact로 적재
- mock-first 후 real adapter 연결

## 8. 릴리즈 관점 가치

### 사용자 가치
- 빠른 의사결정
- 설명 가능한 추천
- 동행 제약 반영 일정

### 운영 가치
- 인기 의도/지역/코스 조합 파악
- planner 품질 개선 데이터 확보

### 확장 가치
- 외부 서비스 embed
- 지역 홍보 랜딩 확장
- AI agent API 제품화

## 9. 제출용 포지셔닝 문장

StoryRoute AI는 한국관광공사 공공데이터를 단순히 보여주는 데서 끝나지 않고, 여행자의 자연어 의도를 이해해 실제 itinerary로 변환하는 **설명 가능한 스마트 관광 탐색 서비스**다.
